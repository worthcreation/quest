Quest: a browser RPG (Zelda meets EarthBound) in a single index.html, hosted at https://worthcreation.github.io/quest/ from the repo worthcreation/quest (personal GitHub account). The repo holds everything: index.html, src/ (source by topic, load order in src/ORDER), tests/, tools/, docs/ (design notes, HISTORY.md, PROJECT_DESCRIPTION.md), HANDOFF.md, QUEST_WAYS_OF_WORKING.md, PROJECT_INSTRUCTIONS.md.

Start of every chat: git clone https://github.com/worthcreation/quest.git into /home/claude, read HANDOFF.md and QUEST_WAYS_OF_WORKING.md in full, then edit the files in src/. Build with: sh build.sh (it also checks the built script parses). While working, run only the tests you touch: node tests/<name>.js (each prints errs N, 0 is a pass). Ship in one call: sh tools/ship.sh NN "Build NN: ..." [scene], which bumps const BUILD in src/draw.js, builds, runs every test (about 2 minutes) and node tools/overlap.js (want 0), packages the zip only if all pass, and prints the ship line and every play-test link.

Delivery: one download per build, quest-bNN.zip, laid out like the repo root (index.html, src/, tests/, tools/, docs/, HANDOFF.md, QUEST_WAYS_OF_WORKING.md, PROJECT_INSTRUCTIONS.md; no node_modules). Deliver the zip as a download, not a preview. Never commit or push from the container: Ross ships from his PC; once he has pushed, reset the clone to origin/main. Every build adds one short entry at the top of docs/HISTORY.md; HANDOFF.md (current state) is updated at a handoff, not every build. At a handoff (end of a chat, or when asked), also refine these project instructions (PROJECT_INSTRUCTIONS.md) to match the source, and the project description (docs/PROJECT_DESCRIPTION.md) only if the game's mood, theme or direction has changed; give both as copyable text for the claude.ai Project, always the full current file (a note of what changed is welcome, but never instead of the whole thing). End each reply with the ship command tools/ship.sh prints for Windows PowerShell (5.1 has no &&, so steps are joined with ;), in a ```powershell code block so it shows in colour:
cd ~\quest -ErrorAction Stop; Expand-Archive -Force ~\Downloads\quest-bNN.zip .; Remove-Item ~\Downloads\quest-bNN.zip; git add -A; git commit -m "Build NN: ..."; git push
(-ErrorAction Stop makes the whole line stop if the folder isn't there, so nothing unzips or deletes in the wrong place; the repo lives at ~\quest, cloned once with: git clone https://worthcreation@github.com/worthcreation/quest.git $HOME\quest (the account in the address keeps it apart from the work GitHub account)) and every play-test link, as full URLs on https://worthcreation.github.io/quest/, as tools/links.js prints them (that file is the one list; if a link is added or renamed in src/, update it in the same build). Always all of them: ?seed=N with a fresh 7-digit prime (the jetty opening), ?arena, ?puzzle, ?mountain (the climb screens; keys 1 to 5, 0 to the first field), ?scene=<id> (start on any screen, including rise and climb1 to climb5), ?overview=N (the same world as one map) and ?model (the drawn hero).

Model: in the first line of every chat's first reply, state which model the task needs, FABLE or Opus, using WAYS section 7a. Use FABLE for anything that changes more than about four interdependent files, any system-wide refactor, joining or restructuring the world, designing a new system, deciding what to do about an audit, or a bug two Opus tries haven't fixed; if unsure, FABLE. When the task needs Fable and the chat is on Opus, stop before any work and say: switch to Fable, with the reason. Opus is for single features, tuning, known-cause bugs, running the audit, mechanical cleanups, docs and handoffs.

Audit: node tools/audit.js (report card, about 6 s) at the start of a cleanup chat and at every handoff (then --save, and its summary line goes in HANDOFF.md). tools/ship.sh stops if node tools/dead.js lists an unused top-level name: delete it, or mark it // keep: <reason>.

Ways of working: build features headlessly and test them with the node harness (tests/<topic>.js through tests/harness.js: eval index.html with a fake canvas, seeded randomness, fixed world seed) before delivering; tests play it like a person (walk, press, wait). Report what was tested, plainly, with numbers. No renders unless Ross asks for them (tools/shot.js); for looks that aren't settled he asks for still mockups first, no build. Suggest a fresh chat every 5 or 6 builds or when the topic changes. Keep arena, puzzle and test modes on the same code as the main game. Lay out anything jumpable in tiles at enterScene, not in screen fractions. Collision and drawing share one shape function; never draw an edge the game doesn't test. Delete what lost its purpose in the same build. No em dashes in replies; concise, candid, no AI-sounding filler.

Design rules to keep: gusts come in sets of three (two gentle, one strong), only the strong one carries you, landing on a ledge; your shadow shows where you'll land (small at the top of a jump, leading toward the landing). Rocks are buried and must be knocked loose (stomp), then rocked and heaved; single cracking boulders take thrown rocks; no pressure plates, logs or ropes. Rough stones are faceted with a zigzag soil line where they meet the ground; throwing stones are lumpy, each its own shape. Say "rich soil", never "tilled"; the shelter is a lean-to, never a tent. One alert style: small scrolls near the bottom (pickups too); full banners only when a quest starts or ends. The HUD sits bottom-right (vigor bar and the A S D F slots) and fades when quiet; the quest note is top-right. R opens the slot wheel; while R is held, A S D F choose which key to set. F at a patch opens the plant/compost menu. The pack is an icon belt; the Map tab is a page for every place you've been, purple where a found mushroom is; nothing about spores until they answer you. Anything you gain shows in the pack. Pip and NPC lines hold until F; tutorial lines are free; Pip teaches in his own bubble and a slot flashes when Pip suggests using it. Pip is "Pip", never "they"; Pip leads on one side of your path at about half your speed. Items rest on the ground and are picked up with F. Skills level quietly: one flavour line per level, details on the Status page. Quests: current objectives on top, folded log below, newest first.

Story so far: you choose a name and colour; the game opens on the old jetty mid-conversation; Pip waits by the garden; the robin hides until you pound by its tree, then drops seeds; plant two (quest: Pip's garden); Pip leads to the camp spot (quest: Set up camp; lean-to already up); gather river stones (the last ones are inside a boulder you break with a stuck stone Pip shows you how to loosen), sticks (a few lying about, the rest shaken from trees with a pound) and rabbit fluff; glue, fire ring and workbench on the mat (3 slots); twilight and the lantern in the lean-to; the woods at dusk: a gremlin peeks, another taunts, then an ambush takes Pip; break the boulders; the sword in a stump by a bramble cluster; the cave; the rescue; spores carry you home; morning, and the journal quest. Beyond: the rise (where f2 was: one long slope from f1 that pulls the view back and tips it as you climb, with f1's wind, two rabbits and cover, and a wall of reeds at x 20 that nothing passes yet), the windy fields and mountain path, the crags and the High Reaches above the old summit, spore travel between found mushrooms, Wick's cellar. The climb screens (climb1 to climb5) are in testing and not yet joined to the world.
